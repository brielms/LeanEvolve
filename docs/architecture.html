LeanEvolve turns open-ended model search into a narrow stream of formal candidates. Search may be creative, stochastic, and wrong. Acceptance is deterministic: named declarations must survive Lean and an explicit axiom policy.

One asymmetry governs the system. Untrusted components may propose anything; they cannot award themselves a single point of verified progress.

From proposal to frontier.

Every transition emits a durable artifact. The final frontier is a chain of candidate sources and kernel receipts, not a story about what the model intended.

01 / SPEC

Pin goals

JSON names declarations, weights, dependencies, limits, and axioms.

02 / PROPOSE

Edit Lean

Shinka supplies a parent; a model edits the bounded evolution block.

03 / CHECK

Run kernel

The complete file elaborates, then each configured declaration is audited.

04 / SCORE

Credit proofs

Only safe declarations whose prerequisites closed contribute weight.

05 / BIND

Record lineage

Parent, source, receipt, model exchange, and frontier are hash-bound.

Three kinds of reproducibility.

Re-running a stochastic search is neither necessary nor sufficient. LeanEvolve preserves the layers that matter separately.

SRC

Input identity

Formal sources, configuration, prompt, and seed are copied into a portable snapshot and represented by SHA-256 records.

WHY

Discovery lineage

Parent links and proposal artifacts explain which accepted frontier a generation extended and what new declarations it closed.

QED

Verification replay

A clean command rebuilds the snapshot and compares fresh kernel results with the saved declaration receipts—without calling the model.

The evidence bundle.

Human-readable enough to inspect, structured enough to verify, and explicit about what each file can—and cannot—establish.

run_manifest.json

Configuration, platform, input records, run status, and final inventory.

events.jsonl

Append-only lifecycle events; each line commits to the preceding line.

gen_N/main.lean

The exact complete candidate supplied to the formal acceptance gate.

evaluation_manifest.json

Candidate and project hashes, axiom receipts, metrics, and toolchain.

proof_lineage.json

Content-addressed parent nodes and the strongest recorded frontier path.

input_snapshot/

Portable copies of the formal project, prompt, seed, and configuration.

Success ends in one boring command.

Discovery can be adventurous. Verification should be wonderfully dull: inspect hashes, rebuild inputs, run Lean, compare receipts, exit zero.

No model call participates in replay
No placeholder or custom assumption enters credit
No manually inspected step is required for acceptance
Any byte-level tampering changes the audit result
